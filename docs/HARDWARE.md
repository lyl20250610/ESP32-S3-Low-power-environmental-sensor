# 硬件接线确认单

> 板卡：**ESP32-S3-DevKitC-1 v1.1** ｜ 模组：**ESP32-S3-WROOM-1-N8R8**（8MB Flash + 8MB Octal PSRAM）
> 本文档是**步骤 0** 的产出，也是步骤 1 烧录前最后一道检查。
> 状态：🟡 步骤 0/1/2 已实测复核（见 §5）｜ ⚠️ DHT11 上拉电阻缺失为**待办项**（见 §2.2）

## 1. 供电与数据线（先看这一节）

| 项 | 要求 | 为什么 |
|---|---|---|
| Type-C 口 | **必须插标着 "UART" 的那个口**，不要用标 "USB" 的口 | UART 口经板载桥接芯片，支持自动复位烧录；原生 USB 口占用 GPIO19/20，且深睡唤醒时 USB 会重新枚举、串口掉线 |
| 供电 | 步骤 1~8 全部用 USB 供电 | 电池方案是步骤 10 |
| 串口波特率 | 115200 | 项目书 6.1 节 |

## 2. 引脚分配表

| 外设 | 模块引脚 | 接到开发板 | 说明 |
|---|---|---|---|
| DHT11（3 针小板上拉） | VCC / + | **3V3（步骤 2~6 常供）** | 步骤 2~6 直接常接 3.3V，对应 `APP_DHT_POWER_GATE_ENABLED 0` |
| DHT11 | DATA / OUT / S | **GPIO4** | ⚠️ **实测这颗模块上没有上拉电阻**（见 §2.2）；目前靠 ESP32 内部约 45 kΩ 工作 |
| DHT11 | GND / − | **GND** | |

> **DHT11 供电的两个阶段**（别混了）：
> - **步骤 2~6：VCC → 3V3 常供**。固件里 `APP_DHT_POWER_GATE_ENABLED = 0`，
>   `app_dht_power_pin()` 返回 `-1`，`dht11_read_once()` 不做任何门控。
>   **DATA 仍然接 GPIO4。**
> - **步骤 7 起（可选省电）：VCC → GPIO5**。DHT11 工作电流约 1mA，
>   GPIO 直驱安全（SGP30 的 48.8mA 就不行）。届时把
>   `APP_DHT_POWER_GATE_ENABLED` 改成 `1` 并重新编译即可，无需改代码。
>
> 注意：GPIO5 在步骤 2~6 期间**空着不接**，别把 VCC 插上去——那样传感器就没电了。
| SGP30（GY-SGP30 类模块） | VCC / VIN | **3V3** | ⚠️ 见下方「SGP30 供电待定」 |
| SGP30 | GND | **GND** | |
| SGP30 | SDA | **GPIO8** | 模块自带 I2C 上拉 |
| SGP30 | SCL | **GPIO9** | 模块自带 I2C 上拉 |

> ⚠️ **DHT11 一律用 3.3V 供电，绝不能接 5V。**
> 5V 供电会把 DATA 上拉到 5V，而 ESP32-S3 的 GPIO **不是 5V 容忍**，会损伤芯片。

### 2.2 ⚠️ DHT11 上拉电阻：实测这颗模块没有，属待办项

**2026-10-11 步骤 2 实测结论**：`stage2_probe_data_line()` 报 `内部上拉时读到 1，内部下拉时读到 0`，而同期传感器**能正常读数并连续 14 次 CRC 通过**。两者结合只能得出一个结论 —— **DATA 线上没有 4.7k~10k 的外部上拉电阻，现在完全靠 ESP32 内部那约 45 kΩ 硬撑**。

（早先"用户已确认是 3 针自带上拉模块"的说法**以本次实测为准，予以更正**。很多便宜 3 针模块只焊了电源 LED，没焊上拉。请目视确认模块上是否有电阻元件。）

| 项 | 现状 |
|---|---|
| 当前能不能用 | **能用** —— 第 3~16 次连续 14 次 CRC 通过 |
| 代价 | 上电冷启动后约 12 秒内 4 次尝试**全部失败**，之后才稳定 |
| 为什么有风险 | 无外部上拉时数据线空闲期处于不确定状态，传感器上电阶段容易漏掉起始信号；线变长 / 受干扰 / 温差大时裕量更薄 |
| 标准修法 | **DATA ↔ 3V3 之间加一颗 4.7 kΩ（10 kΩ 亦可）电阻** |
| 用户决定（2026-10-11） | **暂不加，继续推进**；已记入 `docs/PLAN.md` 风险表 |
| 触发重新评估的条件 | **步骤 7 之前必须解决** —— 若步骤 7 启用 GPIO 门控给 DHT11 供电，每次唤醒都是一次冷启动，可能重现"十几秒读不到"，而每 10 分钟只有一次采样机会 |

### 2.1 ⚠️ SGP30 供电：两种方案，步骤 7 实测后二选一

SGP30 测量模式供电电流高达 **48.8 mA**，而 ESP32 GPIO 单脚长期只能约 20mA、绝对上限约 40mA。
**所以不能像 DHT11 那样用 GPIO 直驱**。两条待选路线：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐先试）** | VCC 直接常接 3.3V，固件只在需要采样时发测量命令 | 接线最简单；若模块静态电流只有几十 µA，就能免掉 15 秒预热，**省电又省时** | 需要先实测「模块待机电流」才能确认 |
| **B** | GPIO（占位 GPIO10）驱动 P 沟道 MOSFET / 负载开关，给整块模块供电 | 待机时彻底断开 | 要新增器件（涉及成本，触发停止条件 3） |

**步骤 7 的裁决依据**：万用表/功耗仪实测模块在"上电但不发测量命令"时的电流。
- ≤ 100µA → 用方案 A
- 100µA ~ 1mA → 灰区，需要你拍板
- \> 1mA 且必须门控 → 用方案 B

## 3. 必须回避的引脚（别在这些脚上接任何东西）

| 引脚 | 用途 | 后果 |
|---|---|---|
| GPIO0 | BOOT 键 / 启动绑带脚 | 上电时电平决定进不进下载模式 |
| GPIO3 | 启动绑带脚（JTAG 源选择） | 同上 |
| GPIO45 / GPIO46 | 启动绑带脚（VDD_SPI 电压 / ROM 打印） | 同上 |
| GPIO26 ~ GPIO32 | 模组内部 SPI Flash | 直接死机 |
| GPIO33 ~ GPIO37 | N8R8 的 Octal PSRAM | 本项目虽然关了 PSRAM，但脚位仍不宜复用 |
| GPIO19 / GPIO20 | 原生 USB D− / D+ | 用 USB 调试时冲突 |
| GPIO43 / GPIO44 | UART0 TX / RX | 串口日志通道 |
| GPIO38 | 板载 WS2812 RGB 灯（v1.1） | 本项目**主动把它钉成输出低**并加电平锁，别接别的 |

> ⚠️ **这个引脚的归属还没被实物证实**：v1.0 板子的 RGB 在 **GPIO48**，v1.1 在 **GPIO38**。
> 依据只是网络搜索摘要（原始页面抓取失败），所以指望"步骤 6 熄灯时看一眼实物"来定案。
> 软件这边已经按 **GPIO38** 写好：上电第一件事配成输出低，深睡期间用
> `gpio_hold_en()` + `gpio_deep_sleep_hold_en()` 把电平锁住
> （`firmware/main/main.c` 的 `board_rgb_led_init()` / `board_rgb_led_hold()`）。
> **如果灯实测没有灭**，把 `firmware/main/app_config.h` 里的 `APP_PIN_RGB_LED`
> 改成 `GPIO_NUM_48` 再烧一次即可 —— 全工程只有这一个宏，别处不用动。
>
> 为什么非要管这个脚：WS2812 的 DIN 悬空时会把噪声当数据、随机锁存出一个颜色，
> 最坏情况三色全亮是几十 mA，足以把平均 1.65mA 的预算整个打穿。

## 4. 步骤 0 需要你现场确认并回报的 6 项

1. 板子丝印版本是 **v1.1** 吗？（用户已口头确认 → 仍需看一眼丝印）
2. 模组丝印是 `ESP32-S3-WROOM-1-N8R8` 吗？
3. 插上 **UART** 口后，设备管理器里新增的 COM 口号（当前已知 COM3 / COM4）？
4. SGP30 模块的丝印型号（GY-SGP30 / 其它）与**引脚丝印顺序**（VCC-GND-SDA-SCL 还是别的顺序）？
5. ~~DHT11 是 3 针小板（自带电阻）还是 4 针裸件（需要外接 4.7k~10k）？~~ **已由步骤 2 实测否证**：是 3 针小板，但**板上没有上拉电阻**（见 §2.2）。
6. DHT11 数据线长度？超过 20cm 时建议缩短或改用带屏蔽的线。
